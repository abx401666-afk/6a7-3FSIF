# Third-party dependencies

This repository uses Git submodules instead of copying third-party library source into `vendor/`.

| Dependency | Submodule path | Upstream | Initial revision | License |
|---|---|---|---|---|
| Dear ImGui | `vendor/imgui` | https://github.com/ocornut/imgui | `v1.93.0` | MIT |
| MinHook | `vendor/minhook` | https://github.com/TsudaKageyu/minhook | `8af6b4a` | BSD-2-Clause |

Run `setup-submodules.ps1` once after extracting this project and before committing it to your own Git repository. The script creates real Git submodule entries and stages them. The `.gitmodules` file is generated by Git when the script runs; a ZIP file cannot itself encode Git's special submodule gitlink entries.

The submodule entries track the upstream `master` branch for tools that explicitly request remote submodule updates, while the initial checkout is pinned to the revisions listed above. A normal `git clone --recurse-submodules` checks out the exact commits recorded by the main repository.

## Generated helper DLL

`res/bcvis.dll` is not committed. It is generated locally from `vistrace/VisTrace.cpp` and the MinHook submodule by `vistrace/build.sh`, then embedded by `res/var.rc` as resource 201. This avoids committing a generated binary that statically contains third-party MinHook code.
